Database overview

The application will use an SQLite database. The database will store users, songs, playlists and the songs added to each playlist.

Four tables are planned for the first version of the application.

Database tables

Tables and fields planned for the application
Table Purpose Fields
Users Stores registered users and administrators. user_id, name, email and role
Songs Stores information about each song. song_id, title, artist, album and genre
Playlists Stores playlists created by users. playlist_id, user_id, name and description
Playlist songs Connects songs to playlists. playlist_id, song_id and position

Table relationships

  • One user can create many playlists.
  • Each playlist belongs to one user.
  • One playlist can contain many songs.
  • One song can appear in many playlists.
  • The Playlist songs table creates the relationship between playlists and songs.

Primary and foreign keys

  • Users: user_id is the primary key.
  • Songs: song_id is the primary key.
  • Playlists: playlist_id is the primary key and user_id is a foreign key.
  • Playlist songs: playlist_id and song_id connect to the Playlists and Songs tables.

Example database queries

Create a playlist

INSERT INTO playlists (user_id, name, description)
VALUES (?, ?, ?);

View songs in a playlist

SELECT songs.title, songs.artist
FROM songs
JOIN playlist_songs
ON songs.song_id = playlist_songs.song_id
WHERE playlist_songs.playlist_id = ?;

Rename a playlist

UPDATE playlists
SET name = ?
WHERE playlist_id = ?;

Delete a playlist

DELETE FROM playlists
WHERE playlist_id = ?;
