Routes overview

A route is a combination of an HTTP request method and a URL. The Music Playlist Manager will use GET requests to display information and POST requests to change information.

GET requests will not change the database. POST requests will create, update or delete database records. The first version will use a test user, so login is outside the current project scope.

GET routes

GET /

Request data: No data is required.

Server action: Displays the application homepage with links to the songs and playlists pages.

SQL: No SQL query is required.

Database side effect: None.

Response: An HTML homepage with status 200 OK.

GET /songs

Request data: No data is required.

Server action: Retrieves and displays all songs in alphabetical order.

SQL:

SELECT * FROM songs
ORDER BY title;

Database side effect: None.

Response: An HTML song catalogue with status 200 OK. The page contains links to individual song pages and a search form.

GET /songs?query=example

Request data: The query string contains the search text.

Server action: Finds songs whose title or artist matches the submitted search.

SQL:

SELECT * FROM songs
WHERE title LIKE ?
OR artist LIKE ?
ORDER BY title;

The server adds percentage symbols to the search value before executing the query.

Database side effect: None.

Response: An HTML page with status 200 OK containing the filtered song results.

GET /songs/:songId

Request data: The song ID is received as a URL parameter.

Server action: Retrieves one song using its ID.

SQL:

SELECT * FROM songs
WHERE song_id = ?;

Database side effect: None.

Successful response: An HTML song-details page with status 200 OK.

Error response: If the song does not exist, the server returns an HTML error page with status 404 Not Found.

GET /playlists

Request data: The current test user's ID is used by the server.

Server action: Retrieves the playlists belonging to the user.

SQL:

SELECT * FROM playlists
WHERE user_id = ?
ORDER BY name;

Database side effect: None.

Response: An HTML page with status 200 OK. It contains the user’s playlists, links to individual playlist pages and a form for creating a playlist.

GET /playlists/:playlistId

Request data: The playlist ID is received as a URL parameter.

Server action: Retrieves the selected playlist and all songs added to it.

SQL:

SELECT * FROM playlists
WHERE playlist_id = ?;
SELECT songs.*
FROM songs
JOIN playlist_songs
ON songs.song_id = playlist_songs.song_id
WHERE playlist_songs.playlist_id = ?
ORDER BY playlist_songs.position;

Database side effect: None.

Successful response: An HTML playlist-details page with status 200 OK. It contains the playlist information, its songs and the management forms.

Error response: If the playlist does not exist, the server returns an HTML error page with status 404 Not Found.

GET /admin/songs

Request data: No form data is required.

Server action: Retrieves all songs for the administrator.

SQL:

SELECT * FROM songs
ORDER BY title;

Database side effect: None.

Response: An HTML administration page with status 200 OK. It contains the new-song form and links for editing existing songs.

GET /admin/songs/:songId

Request data: The song ID is received as a URL parameter.

Server action: Retrieves the song that the administrator wants to edit or delete.

SQL:

SELECT * FROM songs
WHERE song_id = ?;

Database side effect: None.

Successful response: An HTML page with status 200 OK containing pre-filled edit and delete forms.

Error response: If the song does not exist, the server returns an HTML error page with status 404 Not Found.

POST routes

POST /playlists

Request data: Playlist name and description from the form, together with the test user ID.

Server action: Validates the form and creates a new playlist.

Successful response: The server returns 303 See Other with a Location: /playlists header. The browser then sends GET /playlists.

Error response: If the playlist name is missing or invalid, the server returns the form with error messages and status 400 Bad Request.

SQL:

INSERT INTO playlists (user_id, name, description)
VALUES (?, ?, ?);

Database side effect: A new playlist record is created.

POST /playlists/:playlistId

Request data: The playlist ID is received as a URL parameter, and the new name and description come from the edit form.

Successful response: The server returns 303 See Other with a Location: /playlists/:playlistId header. The browser then sends GET /playlists/:playlistId.

Validation error: If the submitted name is missing or invalid, the server returns the form with error messages and status 400 Bad Request.

Not-found error: If the playlist does not exist, the server returns an HTML error page with status 404 Not Found.

Server action: Validates the form and updates the selected playlist.

SQL:

UPDATE playlists
SET name = ?, description = ?
WHERE playlist_id = ?;

Database side effect: The playlist record is updated.

POST /playlists/:playlistId/delete

Request data: The playlist ID is received as a URL parameter.

Server action: Removes the playlist-song connections and then deletes the playlist.

SQL:

DELETE FROM playlist_songs
WHERE playlist_id = ?;
DELETE FROM playlists
WHERE playlist_id = ?;

Database side effect: The playlist and its playlist-song records are deleted. Song records are not deleted.

Successful response: The server returns status 303 See Other with Location: /playlists. The browser then requests GET /playlists.

Not-found error: If the playlist does not exist, the server returns an HTML error page with status 404 Not Found.

POST /playlists/:playlistId/songs

Request data: The playlist ID from the URL and the selected song ID from the form.

Server action: Adds the selected song to the playlist.

SQL:

INSERT INTO playlist_songs
(playlist_id, song_id, position)
VALUES (?, ?, ?);

Database side effect: A new relationship is created between the playlist and song.

Successful response: The server returns status 303 See Other with Location: /playlists/:playlistId. The browser then requests GET /playlists/:playlistId.

Validation error: If no song is selected, the server returns the form with an error message and status 400 Bad Request.

Not-found error: If the playlist or song does not exist, the server returns an HTML error page with status 404 Not Found.

POST /playlists/:playlistId/songs/:songId/delete

Request data: The playlist ID and song ID are received as URL parameters.

Server action: Removes the selected song from the playlist.

SQL:

DELETE FROM playlist_songs
WHERE playlist_id = ?
AND song_id = ?;

Database side effect: The playlist-song relationship is deleted. The song remains in the catalogue.

Successful response: The server returns status 303 See Other with Location: /playlists/:playlistId. The browser then requests GET /playlists/:playlistId.

Not-found error: If the playlist, song or relationship does not exist, the server returns an HTML error page with status 404 Not Found.

POST /admin/songs

Request data: Song title, artist, album and genre from the administration form.

Server action: Validates the form and creates a new song.

SQL:

INSERT INTO songs (title, artist, album, genre)
VALUES (?, ?, ?, ?);

Database side effect: A new song record is created.

Successful response: The server returns status 303 See Other with Location: /admin/songs. The browser then requests GET /admin/songs.

Validation error: If required song information is missing or invalid, the server returns the form with error messages and status 400 Bad Request.

POST /admin/songs/:songId

Request data: The song ID from the URL and the title, artist, album and genre from the edit form.

Server action: Validates the submitted information and updates the song.

SQL:

UPDATE songs
SET title = ?, artist = ?, album = ?, genre = ?
WHERE song_id = ?;

Database side effect: The song record is updated.

Successful response: The server returns status 303 See Other with Location: /admin/songs/:songId. The browser then requests GET /admin/songs/:songId.

Validation error: If required song information is missing or invalid, the server returns the form with error messages and status 400 Bad Request.

Not-found error: If the song does not exist, the server returns an HTML error page with status 404 Not Found.

POST /admin/songs/:songId/delete

Request data: The song ID is received as a URL parameter.

Server action: Removes the song from all playlists and then deletes the song.

SQL:

DELETE FROM playlist_songs
WHERE song_id = ?;
DELETE FROM songs
WHERE song_id = ?;

Database side effect: The song and its playlist-song relationships are deleted.

Successful response: The server returns status 303 See Other with Location: /admin/songs. The browser then requests GET /admin/songs.

Not-found error: If the song does not exist, the server returns an HTML error page with status 404 Not Found.

Forms and links

  • The song catalogue links to individual song pages.
  • The search form sends a GET request to /songs.
  • The playlist creation form sends a POST request to /playlists.
  • Playlist edit, delete, add-song and remove-song forms use the playlist POST routes.
  • The administration pages contain forms for creating, editing and deleting songs.
  • Every POST route redirects to a GET route after completing the database operation.

Prototype user journey

The following journey demonstrates how a user can move through the application prototypes.

  1. Start on the application homepage.
  2. Open the song catalogue and search for a song.
  3. Select a song to open its individual details page.
  4. Open My playlists to view or create a playlist.
  5. Select a playlist to open its playlist-details page and manage its songs.
  6. An administrator can open the song administration page to add songs.
  7. The administrator can use the edit and delete song page for an existing song.
